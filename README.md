# Retail Inventory Risk Radar

**Stockout early warning for a multi-store grocer, built end to end on Databricks.**

Harvest Lane Markets (fictional; 50 stores, 5 regions, 400 SKUs) reviews sales, inventory, purchase orders, promotions and supplier lead times in separate systems and reports. Planners find out an item has run out when the shelf is empty. The Risk Radar brings those signals together every morning to:

1. forecast demand for each store/SKU for the next 28 days,
2. compare expected demand over each item's replenishment lead time with on-hand plus inbound stock,
3. rank the likely stockouts, explain the drivers in units, and suggest an action (expedite, transfer, reorder).

Planners decide, and their decisions are recorded. **Nothing is ordered automatically.**

> All data is synthetic, generated by `src/datagen/generate_raw_data.py`. No customer data is used.

**How this was built:** [`BUILD_LOG.md`](BUILD_LOG.md) covers the workflow with Claude Code: what was asked, the timeline, where AI sped things up, and where it changed design decisions.

## End-to-end journey

| Stage | What runs | Where |
|---|---|---|
| **Lakeflow** (ingest) | Auto Loader streaming tables for append-only POS, inventory and PO events; expectations in silver; materialized views in gold | `src/pipeline/`, `resources/pipeline.yml` |
| **Unity Catalog** (govern) | One schema for files, tables, model, functions and metric views. Comments, policy-compliant tags, lineage, an **enforced row filter + column mask** on the planner queue (tested every run), least-privilege grants, app SP grants | `src/governance/`, `src/metrics/` |
| **ML** (intelligent) | Seasonal-naive baseline vs global LightGBM (MLflow), champion registered in UC with `@champion`, **daily drift check that triggers retraining** through a condition task, batch 28-day forecast | `src/ml/` |
| **Risk scoring** (transparent) | Lead-time demand vs on hand + projected inbound, stockout probability, revenue at risk, quantified drivers, suggested action; unit-tested | `src/risk/risk_logic.py`, `tests/` |
| **Gen AI** | `ai_query` (Claude Haiku on Databricks) turns the quantified facts into a two-sentence planner note; **evaluated** by deterministic checks + an LLM judge (Claude Sonnet), logged to MLflow, failing notes fall back to the template | `src/risk/genai_explanations.py`, `src/risk/evaluate_explanations.py` |
| **Lakebase** (operational serving) | Autoscaling Postgres. A snapshot synced table is the app's read model; app tables hold decisions, overrides, notes and watchlists; these are exported back to Delta | `resources/lakebase.yml`, `src/lakebase/` |
| **Genie** (natural language) | Genie space with the retailer's metric definitions, business guidance and certified SQL over tables and metric views; it can **explain a specific recommendation** using the planner note and drivers | `src/genie/`, `resources/genie.yml` |
| **Databricks App** (business) | Streamlit planner UI: ranked queue, drill-down, decision capture, watchlist, action KPIs, "Ask Genie" | `src/app/`, `resources/app.yml` |
| **AI/BI dashboard** | Ranked exceptions, revenue at risk, drivers, cover/excess, forecast accuracy, alert quality, supplier performance | `src/dashboards/`, `resources/dashboard.yml` |

Architecture and design decisions: [`docs/architecture.md`](docs/architecture.md). KPI definitions: [`docs/metric_definitions.md`](docs/metric_definitions.md).

## Deploy and run

Prerequisites: Databricks CLI v1.20+ with a profile for the workspace, permission to create a schema in the target catalog, and Lakebase Autoscaling enabled.

```bash
databricks bundle validate
databricks bundle deploy                         # schema, volumes, pipeline, job, experiment, model, Lakebase, Genie, dashboard, app
databricks bundle run inventory_risk_radar_e2e   # datagen -> pipeline -> drift check -> (retrain if needed) -> forecast -> risk -> Gen AI -> note eval -> governance -> metric views -> Lakebase
databricks bundle run planner_app                # start the planner app
```

Re-capture evidence after a run:

```bash
uv run --with databricks-sdk python scripts/export_run_notebooks.py <job_run_id>
GENIE_SPACE_ID=<id> uv run --with databricks-sdk --with "psycopg[binary]" python scripts/capture_evidence.py <job_run_id>
uv run --with pandas,numpy,scipy,pytest pytest -q tests/test_risk_logic.py
```

Change `catalog`, `schema`, `warehouse_id`, `lakebase_owner_role` and the workspace host in `databricks.yml` to deploy elsewhere.
